# 编辑模式：在阅读器里直接修改本地文档并保存

## PRD

### 背景

mdnotate 目前只能读和标注。读的时候经常发现错别字、过时的句子或者想顺手补一行，现在只能切到别的编辑器去改，改完回来再刷新。并且一刷新，这篇文档上做过的所有高亮和评论都会因为「文档已变化」被整批丢弃 —— 改一个字就丢光标注。

### 目标

在 mdnotate 里就能把正在读的本地文档切成代码编辑器修改、手动保存；保存后已有的标注尽量跟着文字走，只有真找不到的才丢弃。

### 功能与交互

**入口：Edit / View 按钮**

- 顶栏 Export Annotation 按钮的左边新增一个按钮，阅读时显示为蓝色的「Edit」（铅笔图标）。
- 点击后进入编辑模式：正文区域变成代码编辑器，按钮原地变为深色的「View」（深色主题下反转为浅底深字）。View 和 Edit 是同一个按钮，位置不动。
- 只有本地文件可以编辑。ssh 远端文档和剪切板文档的按钮置灰，悬停说明原因。
- 换到另一篇文档时总是回到阅读模式。

**编辑器**

- 代码风格的 Markdown 编辑器：等宽字体、行号、语法高亮、当前行高亮、长行自动折行（正文区域不横向滚动）。
- 纯文本类文档（.txt / .json / .log 等）同样可编辑，只是没有 Markdown 高亮。
- 撤销 / 重做、编辑器内查找（⌘F）、全选（⌘A 只选编辑器里的全部文本）都按编辑器的习惯工作。
- 深色 / 浅色主题都要好看，跟随 app 的主题；字号跟随该格式的排版设置。
- 编辑模式下：左侧目录和右侧标注列表变淡且不可点；Export Annotation 置灰（悬停提示先切回 View）；状态栏不再显示源码视图开关，改为提示「⌘S to save」。

**保存**

- 不提供保存按钮，⌘S 保存。保存后仍停留在编辑模式。
- 有未保存的改动时，顶栏中间的文件名后面显示「— Edited」，保存后消失。改回和原文一模一样时也视为没有改动。
- 保存会保留文件原有的换行风格（CRLF 文件仍是 CRLF）和开头的 BOM。
- 如果打开之后文件在别处被改过，保存时先弹窗：「文件在磁盘上已被修改，是否覆盖？」覆盖 / 取消。
- 保存失败（无权限、磁盘满等）在顶栏下方的错误条里说明原因，改动保留在编辑器里，仍处于编辑模式。

**保存后标注的去留**

- 保存后，用每条标注引用的原文到新内容里重新找位置：找到唯一一处就移过去；有多处就取离原来位置最近的一处；找不到（引文本身被改了或删了）才丢弃。
- 有丢弃时在错误条里提示「N 条标注在保存后找不到原文，已移除」。全部找到则不提示。
- 切回 View 后，高亮出现在新的位置，标注列表顺序随之更新。

**离开编辑模式的确认**

以下任何一种操作，若有未保存的改动，都会先弹出系统对话框「Do you want to save the changes you made to “文件名”?」，三个按钮 Save / Don't Save / Cancel：

1. 点 View；
2. 关闭窗口（红色按钮或 ⌘W）；
3. ⌘Q 退出 app（有多个窗口时逐个确认；中途取消则停止退出，已关掉的无改动窗口不恢复）；
4. 在本窗口里打开别的东西：⌘O 面板、把文件拖进窗口、从首页的 Recent 打开、刷新按钮、在 Finder 里再次打开同一篇文档。

- Save：保存成功后继续原来的操作（切到 View / 关窗 / 退出 / 打开另一篇）；保存失败或取消了覆盖确认，则停在编辑模式。
- Don't Save：丢弃改动，继续原来的操作。
- Cancel：什么都不做，留在编辑模式。
- 没有未保存的改动时，以上操作直接进行，不弹窗。
- 打开设置页、导出页、首页只是盖在上面，不算离开，回来时编辑器原样还在。

### 不做的事

- 不编辑 ssh 远端文件、不编辑剪切板文档。
- 不做自动保存，不做保存按钮。
- 不做所见即所得编辑、不做编辑与预览分栏。
- 不处理从 Dock 菜单退出、注销 / 关机时的未保存改动（系统层面拦不住，见 Tech Design 风险）。
- 不把「重新定位标注」推广到「文件在外部被改过后重新打开」的场景（那是另一件事）。
- 编辑器内不做代码块里各语言的语法高亮。

### 验收标准

1. 本地 Markdown 文档的顶栏 Export 左侧有蓝色 Edit 按钮；点击后正文变为编辑器，按钮变为深色 View，位置不变。
2. ssh / 剪切板文档的 Edit 按钮置灰并有原因提示。
3. 编辑后标题出现「— Edited」；⌘S 后消失，磁盘文件内容已更新；把文字改回原样，「— Edited」消失。
4. CRLF 文件、带 BOM 的文件保存后，换行风格和 BOM 不变。
5. 文件打开后被外部修改，⌘S 时弹出覆盖确认；取消则文件不变、仍有「— Edited」。
6. 有标注的文档，在标注之外的地方改字并保存，切回 View 后所有高亮仍在正确的句子上；改掉某条标注的原文后保存，该标注消失并有数量提示。
7. 有未保存改动时点 View / 关窗 / ⌘Q / ⌘O 打开别的文档 / 刷新 / 拖入文件，都会弹三按钮确认，三个按钮行为符合上文；没有改动时不弹。
8. 编辑器中中文输入法组字时按 Enter / Esc 行为正常；⌘A 选中全部文本、⌘Z 撤销、⌘F 在编辑器内查找。
9. 深浅两种主题下编辑器配色正常；编辑模式下目录和标注列表变淡不可点，Export 置灰。

## Tech Design

### 现状

- **阅读器** `src/components/Reader.tsx`：中栏是 `scrollRef` 滚动容器 → `annotator.containerRef`（`.prose-column`）→ `<article>`（Markdown 渲染或 `prose-plain` 原文）+ `CommentMarkers` + `AnnotationPopup`。源码视图 `sourceView` 是局部 state，切换时标注层销毁（`enabled: !!content && !showingSource`），两侧栏经 `PanelContent inert` 变淡。Reader 从不卸载。
- **标注锚点**：`Annotation.start/end` 是「标注容器内、跳过 `.not-annotatable` 子树的文本」的字符偏移（recogito `Ye()` / `Xe()`，`node_modules/@recogito/text-annotator/dist/text-annotator.es.js`），`quote` 是选区的 `Range.toString()`。库恢复高亮时只按偏移、不校验 quote。
- **失效规则**：`open-doc.ts` 的 `open()` 用 `annotationContentHash(content, format)` 算哈希，`restoreAnnotations(docId, hash)`（`annotations-db.ts`）把 `doc_hash` 不同的行直接 `DELETE`。标注层 key 是 `docId#contentHash`（`use-text-annotator.ts`），只在创建时从 store 读一次标注。
- **store** `src/store.ts`：`doc`、`annotations`、`openDoc(doc, annotations)` 一次写入并关闭 ⌘O 面板。
- **打开入口** `src/lib/open-doc.ts`：`openSpec` → `openLocator`（领号、读取、`open()`），`openClipboardText`、`openRecent`、`reloadDoc`、`openSampleDoc`。失败时 `announceDoc()`。Rust 侧 `open_spec()` / `choose_target()` 在路由时就把窗口标成持有该文档；同一文档再次打开会 `emit_to` 回原窗口重新读取。
- **顶栏** `src/App.tsx`：Home / 刷新 / `DocTitle` / Export Annotation（amber）/ Settings / 右栏开关。`DocTitle.tsx` 居中显示标题。
- **键盘**：`use-doc-search.ts` 在 document 上监听 ⌘F/⌘G/Esc（`enabledRef`）；`use-select-all.ts` 在 capture 阶段拦 ⌘A，只放行 `input` / `textarea`，其余一律 `stopImmediatePropagation`。
- **Rust** `src-tauri/src/lib.rs`：`read_local_file` 返回 canonical 路径、内容、`modified`（毫秒，`modified_millis()`）；本地文件 doc 的 `source` 就是 canonical 路径（`formatLocator`）。没有写文件的 command。
- **菜单** `src-tauri/src/menu.rs`：在 `Menu::default()` 上给 File 插 New Window / Open…。macOS 的 App 子菜单是第一个子菜单，最后一项是 `PredefinedMenuItem::quit`（tauri 2.11.5 `menu/menu.rs`）。
- **tao 0.35.3 的 macOS app delegate 没有实现 `applicationShouldTerminate:`**，⌘Q 直接进 `applicationWillTerminate` 退出，`RunEvent::ExitRequested` 拦不住（只在最后一个窗口销毁时触发）。
- **对话框**：`tauri-plugin-dialog` 2.7.2 的 `message()` 支持 `buttons: { yes, no, cancel }` 自定义文字，返回 `'Yes' | 'No' | 'Cancel' | 自定义文字`（macOS 下 rfd 对自定义按钮返回按钮文字）。
- **权限**：`capabilities/default.json` 没有 `core:window:allow-destroy`；JS 的 `onCloseRequested` 在未 `preventDefault` 时调用 `destroy()`。

### 方案

编辑器选 **CodeMirror 6**，自己写一层薄 hook 而不用 `@uiw/react-codemirror`。编辑模式的状态（`editing`、`dirty`）进 store 供界面读，编辑器文本只活在 CM 里；所有编辑相关的动作经一个新漏斗 `edit-session.ts`（与 `annotate.ts`、`open-doc.ts` 同一思路）。

编辑模式下**渲染好的正文不卸载、只隐藏**，编辑器作为中栏的另一个子节点盖上。保存后 store 的 `content` 更新，隐藏的正文随之重新渲染，Reader 的一个 effect 立刻从 DOM 收集新的可标注文本、按引文重新定位标注、写回 store 和库。store 新增 `annotationsHash` 表示「当前这批标注的偏移是对哪个内容哈希量的」，它与 `doc.contentHash` 不等时标注层不启用，等重新定位完成再从 store 重建。

关键决策：

| 决策 | 理由 | 否决的备选 |
|---|---|---|
| CodeMirror 6 | 模块化、体积小；contenteditable + 自己处理 composition，中文输入法在 WebKit 下表现好；主题可直接用 CSS 变量接 neutral 色阶；自带撤销、搜索、keymap | Monaco：数 MB + web worker，WebKit 输入法问题有前科，主题接不上变量。Milkdown / Tiptap / MDXEditor：所见即所得，保存时重排 Markdown 产生无关 diff |
| 自写 `use-code-editor` hook | 需要精确控制：⌘S 由 document 级监听统一处理、dirty 基线在保存时替换、换文档时整个销毁。项目已有自封装 recogito 的先例 | `@uiw/react-codemirror`：props 驱动 `value` 容易在保存/重渲染时回写覆盖光标与撤销历史 |
| 保存后立即重新定位（正文隐藏而非卸载） | 库里的标注任何时候都与磁盘文件一致；⌘S 后直接关窗也不丢标注 | 回到 View 时再定位：⌘S 后直接关窗，库里仍是旧哈希，下次打开被 `restoreAnnotations` 全删 |
| 引文精确匹配，多处取离旧 `start` 最近 | 规则简单可测；标注本来就要求不改渲染文本 | 模糊匹配（diff-match-patch）：引文被改了还硬找，容易高亮到错的句子，违背「宁可丢弃也不高亮错」 |
| 只在 `editing` 时注册 `onCloseRequested` | 不编辑时关窗行为与现在完全一致（不经 JS） | 常驻监听：所有窗口的关闭都绕一圈 JS `destroy()` |
| ⌘Q 换成自定义 Quit 项：逐个 `close()` 窗口 | 复用每个窗口自己的关窗确认；tao 不支持 `applicationShouldTerminate` | Rust 维护 dirty 注册表再协调确认：多一套跨窗口状态 |
| 写文件原地覆盖（`std::fs::write`），按 mtime 判冲突 | 保留 inode、硬链接、权限与扩展属性；本地写入快 | 临时文件 + rename：会换 inode，打断外部 watcher 与硬链接 |
| ⌘S 用 document 级 keydown，不加 File ▸ Save 菜单项 | 一处实现，焦点在编辑器外也生效；CM 默认不绑 Mod-s | 菜单项：需要 Rust → `emit_to` → 前端的整条链路，且启用状态难以随编辑模式变化 |

### 数据变动

- **无 schema 变化、无 migration。** 重新定位后对已有行 `UPDATE annotations SET doc_hash, start_offset, end_offset`，找不到的 `DELETE`。
- **store** 新增：`editing: boolean`、`dirty: boolean`、`annotationsHash: string | null`。
- **设置**：无新增项。
- **Rust**：新 command `write_local_file`，返回 `WriteOutcome`（`{ kind: 'saved', modified }` / `{ kind: 'conflict' }`）；真正的写失败才是 `Err(String)`。冲突做成返回值而不是错误类型：它是一个需要用户回答的结果，这样前端的写文件函数也不需要 try/catch 去区分两种拒绝。

### 逻辑变动

**新增 `src/lib/reanchor.ts`**

- `reanchorAnnotations(annotations: Annotation[], text: string): { kept: Annotation[]; lost: Annotation[] }` —— 纯函数。对每条标注在 `text` 中找 `quote` 的全部出现位置（`indexOf` 循环），取 `|pos - start|` 最小的一处，`start = pos`、`end = pos + quote.length`，其余字段（id、comment、createdAt、updatedAt）不变；空 quote 或找不到进 `lost`。`kept` 经 `sortAnnotations` 排序。
- `collectAnnotatableText(container: HTMLElement): string` —— DOM 那半：`TreeWalker(SHOW_TEXT)`，`parentElement.closest('.not-annotatable')` 的跳过，拼接 `textContent`。与 recogito 的偏移口径一致（引用 `NOT_ANNOTATABLE_CLASS`）。

**新增 `src/lib/edit-text.ts`**（纯函数）

- `splitForEditor(content): { text; bom: boolean; eol: '\n' | '\r\n' }`：去掉开头 `﻿`；全部换行都是 `\r\n` 时 `eol = '\r\n'` 并把 text 转成 `\n`；否则 `eol = '\n'`、text 原样（CM 会把零星的 `\r\n` 归一化，混合换行的文件保存后统一为 LF）。
- `joinFromEditor(text, meta): string`：按 meta 还原 BOM 与 CRLF。

**`src/lib/recent-docs.ts`**

- 新增 `describeEdit(doc: OpenDoc | null): { canEdit: boolean; title: string }`，写法同 `describeReload`：`file` → 可编辑（title `Edit this document`）；`ssh` → `Editing remote files is not supported yet`；`clipboard` → `Clipboard text has no file to save to`；无文档 → 不可。

**新增 `src/lib/edit-prompts.ts`**

- `askToSave(title): Promise<'save' | 'discard' | 'cancel'>`：`message('Do you want to save the changes you made to “<title>”?', { kind: 'warning', buttons: { yes: 'Save', no: "Don't Save", cancel: 'Cancel' } })`，结果经纯函数 `saveChoiceOf(result)` 映射（`'Yes'`/`'Save'` → save，`'No'`/`"Don't Save"` → discard，其余 cancel）。浏览器模式降级：`window.confirm('Save changes…?')` → save；否则再 `confirm('Discard changes?')` → discard / cancel。
- `askToOverwrite(title): Promise<boolean>`：`“<title>” has been changed on disk since it was opened. Overwrite it?`，按钮 `{ ok: 'Overwrite', cancel: 'Cancel' }`；浏览器降级 `window.confirm`。

**新增 `src/lib/edit-session.ts`** —— 编辑的唯一漏斗，模块级即窗口级

- `attachEditor(editor: LiveEditor): () => void`：`use-code-editor` 挂载时登记，卸载时注销。`LiveEditor` = `{ text(): string; markSaved(text: string): void; meta: EditMeta }`（接口只用字符串，测试不必构造 CM 的 `Text`；hook 内部把基线存成 `Text` 以便 `eq` 比较）。
- `startEditing()`：`describeEdit(doc).canEdit` 才 `setEditing(true)`。
- `stopEditing(): Promise<void>`（View 按钮）：`confirmLeaveEdits()` 为真则 `setEditing(false)`。
- `saveEdits(): Promise<boolean>`（⌘S）：同一时刻只跑一次（复用进行中的 promise）。取 `text = live.text()` → `joinFromEditor` → `writeDocFile(doc.source, content, doc.modifiedAt)`；冲突 → `askToOverwrite`，同意则不带 expected 再写一次，否则返回 false。成功后（若窗口里还是这篇文档）先 `applySave`，再 `live.markSaved(text)`（保存期间继续打的字仍算未保存）、`store.applySave({ content, contentHash: annotationContentHash(content, format), modifiedAt })`、`recordOpen(...)` 刷新 Recent 的摘要与字数（不 await，失败报错）。写失败 `setError('Could not save: …')` 返回 false。
- `confirmLeaveEdits(): Promise<boolean>`：不在编辑或不 dirty → true；否则 `askToSave`：save → `saveEdits()` 的结果；discard → true；cancel → false。
- `rebaseAfterSave(text: string)`：Reader 的 effect 调用。`reanchorAnnotations(annotations, text)` → `store.rebaseAnnotations(kept, contentHash)` → `annotations-db.rebaseAnnotations(docId, contentHash, kept, lostIds)`（失败报错）→ `lost.length > 0` 时 `setError('N annotation(s) could not be found after saving and were removed')`。
- `writeDocFile` 单独放在 `src/lib/doc-file.ts`（测试里整个 mock 掉）：Tauri 下 `invoke('write_local_file', { path, content, expectedModified })`，返回 `{ kind: 'saved', modifiedAt } | { kind: 'conflict' }`；浏览器下直接返回 saved + `Date.now()`（让 `pnpm dev` 能走通整个流程）。

**新增 `src/lib/use-code-editor.ts`**

- `useCodeEditor({ parentRef, content, format })`：effect 中创建 `EditorView`（`EditorState.create`），扩展：`lineNumbers()`、`highlightActiveLine()`、`highlightActiveLineGutter()`、`history()`、`EditorView.lineWrapping`、`search({ top: true })`、`keymap.of([...defaultKeymap, ...historyKeymap, ...searchKeymap])`、markdown 文档加 `markdown({ base: markdownLanguage })`、`syntaxHighlighting(<自定义 HighlightStyle>)`、`EditorView.theme(...)`（颜色全部用 `var(--color-neutral-*)` / `var(--prose-*)`，与 neutral 反转方案一致；字体等宽，字号 `calc(var(--prose-font-size) * 0.9)`，行高 `var(--prose-line-height)`）、`EditorView.updateListener`（`docChanged` 时 `dirty = !state.doc.eq(baseline)`，值变化才写 store）。
- 创建后 `attachEditor(...)` 并 `view.focus()`；cleanup 时 `view.destroy()` + 注销。只在挂载时读一次 `content`（之后的 store 变化来自保存本身，不回写编辑器）。
- 编辑器高度随内容增长，滚动交给外层滚动容器（CM 支持祖先滚动容器的视口计算）。

**新增 `src/components/CodeEditor.tsx`**

- 一个带 `typographyVars` 的滚动容器 + `.prose-column mx-auto px-8 py-6` 里放 CM 的挂载点。只在 `editing` 时渲染，退出即卸载（丢弃编辑器状态）。

**`src/store.ts`**

- 新字段 `editing`、`dirty`、`annotationsHash`；动作 `setEditing(editing)`（退出时同时 `dirty: false`）、`setDirty(dirty)`、`applySave({ content, contentHash, modifiedAt })`（只改 `doc` 的这三项，`dirty: false`，不动 `annotations` / `annotationsHash`）、`rebaseAnnotations(annotations, hash)`（`annotations` + `annotationsHash`）。
- `openDoc` 额外重置 `editing: false, dirty: false, annotationsHash: doc.contentHash`。

**`src/lib/annotations-db.ts`**

- 新增 `rebaseAnnotations(docId, docHash, kept: Annotation[], lostIds: string[])`：对 kept 逐条 `UPDATE … SET doc_hash = $1, start_offset = $2, end_offset = $3 WHERE id = $4`，lostIds `DELETE`。浏览器 fallback 同步改 localStorage 里的行。

**`src/lib/open-doc.ts`**

- 新增内部 `mayReplace(): Promise<boolean>` = `confirmLeaveEdits()`，为假时 `announceDoc()`（把 Rust 注册表里被路由改掉的 doc id 改回来）并返回。
- 在 `openLocator`、`openClipboardText`、`openRecent`（剪切板分支）开头调用；`openSpec` / `reloadDoc` / 文件分支经 `openLocator` 自然覆盖。领号 `opens.start()` 放在确认之后。

**`src/components/Reader.tsx`**

- 读 `editing`、`annotationsHash`。
- `editing` 变为 true 时 `setSourceView(false)`。

### 风险与待定

- **⌘Q 之外的退出路径不受保护**：Dock 菜单「退出」、注销 / 关机走 `terminate:`，tao 没有 `applicationShouldTerminate:`，未保存改动会丢。记入 `kb/known-issues.md`。
- **自定义 Quit 的顺序关窗**：先关掉的无改动窗口不会因后面的取消而恢复（PRD 已接受）。
- **macOS 三按钮对话框的返回值**：预期 rfd 对自定义按钮返回按钮文字，`saveChoiceOf` 同时接受 `Yes/No` 与文字；需实机确认 Esc 落在 Cancel、Return 落在 Save。
- **⌘Z / ⌘A 在 WKWebView 里先到 JS 还是先到菜单**：现有 ⌘A 拦截说明 keydown 先到页面，预期 CM 的 keymap 能先处理；需实机确认撤销不走菜单的原生 undo。
- **隐藏的正文**：`hidden`（display:none）下文本节点仍在，`collectAnnotatableText` 不依赖布局；切回 View 时滚动位置可能回到顶部，可接受。
- **大文档**：dirty 判断用 `Text.eq`，长度不同时立即返回；长度相同（如撤销回原样）才逐块比较。保存时隐藏正文重渲染一次 Markdown。
- **`write_local_file` 是同步 command**：本地写入毫秒级，不会冻住窗口；若将来支持网络盘再改 async。
