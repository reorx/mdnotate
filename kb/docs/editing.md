# 编辑模式

写给要改编辑功能的人：本地文档怎么切进编辑器、什么时候算未保存、保存时发生了什么、标注怎么跟着文字走，以及哪些操作会先问一句「要不要保存」。

## 进出编辑模式

顶栏 Export Annotation 左边是 Edit / View 按钮，一个按钮两种状态：阅读时是蓝色的 Edit，编辑时原地变成深色的 View（深色主题下反成浅底深字）。按钮位置不动，进来和回去都在同一个指针下面。

只有本地文件能编辑，按钮对其余文档置灰并说明原因：

- 剪切板文档的正文只存在库里，id 是内容哈希，「保存」等于变成另一篇文档。
- ssh 远端文件理论上能写回，但网络在写到一半时断开会在远端留下半截文件，不该作为顺手的功能带进来。

编辑模式下正文区域换成 CodeMirror 6 编辑器：等宽、行号、Markdown 高亮、自动折行，撤销 / 查找（⌘F 是编辑器自己的搜索面板）/ 全选都是编辑器的。两侧栏变淡且不可点，Export 置灰（标注可能随下一次保存移动），状态栏不再显示复制和源码视图按钮，只提示「⌘S to save」。

换到另一篇文档总是回到阅读模式；编辑状态不跨文档，也不进设置。

### 为什么自己封装 CodeMirror

React 封装通常用 `value` prop 驱动编辑器，方向反了：store 里的正文只在保存时才变，回灌进编辑器会在用户最不期望的时刻重置光标和撤销历史。所以编辑器挂载时读一次正文，之后自己拥有文本；需要保存时由会话去问它要。

选 CodeMirror 6 而不是 Monaco：体积小、按需装；contenteditable + 自己处理输入法组字，在 macOS WebKit 下中文输入正常；颜色可以直接引用 app 的 CSS 变量，于是 neutral 色阶的反转（见 `theme-and-typography.md`）自动给了编辑器深色模式。所见即所得的方案（Milkdown、Tiptap）被否决：它们保存时会重排 Markdown，产生用户没做过的改动。

## 未保存与保存

**没有保存按钮，⌘S 保存。** 未保存的唯一提示是顶栏文件名后面的「— Edited」。

「未保存」的意思是「和文件里的不一样」，不是「上次保存后动过」：撤销回原样，「— Edited」就消失。

保存时：

- 写的是用户原来的文件加上他的改动，不多也不少。编辑器内部只认 `\n`、不认 BOM，所以全程 CRLF 的文件进编辑器前转成 LF、保存时转回去，开头的 BOM 同理剥掉再补回。换行混杂的文件没有单一惯例可保留，保存后统一为 LF。
- 原地写入，不走「临时文件 + 改名」：改名会换 inode，打断硬链接、丢掉扩展属性，还会让外部编辑器和 watcher 以为文件被删了。本地写一个文本文件足够快，用不着改名换来的那点原子性。
- **按修改时间判冲突。** 打开（或上一次保存）时记下文件的修改时间，保存前对比磁盘上的；不一样说明别的程序写过它，直接覆盖会把那份改动悄悄丢掉。这时什么都不写，先问「是否覆盖」。文件已经不在、或文件系统不记时间，就直接写回。
- 没有改动时 ⌘S 什么都不做。照写不误会白白刷新修改时间；文件刚在外部被改过时，还会问要不要拿用户根本没动过的文本去覆盖。
- 同一时刻只跑一次保存：连按 ⌘S 共享第一次的结果，否则第二次写会被第一次写出的新修改时间判成冲突。
- 保存期间继续打的字不算进这次保存，仍是未保存。
- 写失败（权限、磁盘满）在错误条里说明原因，改动留在编辑器里。

## 保存后的标注

标注锚定在渲染文本的字符偏移上（见 `annotations-and-export.md`），所以文件变了，偏移就指向别的字。从外部改过的文件重开时，这些标注会被整批丢弃；**在 app 里保存不同**：标注还在手上，每条都带着自己高亮的原文，凭原文就能在新文本里找回位置。

规则：

- 只认**精确匹配**。原文不再原样出现，说明它本身被改了；去猜一个相近的句子，就是在用户没选过的地方画高亮 —— 正是失效规则要防的事。
- 出现多处时取离原位置最近的一处：编辑相对于全文长度只会挪动很小的距离。
- 找不到的丢弃，错误条提示丢了几条；全部找到则不提示。

实现上有两个必须的配合：

- **编辑模式下渲染好的正文只隐藏、不卸载。** 重新定位要用新内容的渲染文本，偏移口径必须和标注库一模一样（跳过 `not-annotatable` 子树），只有真实 DOM 给得出来。保存后 store 里的正文一换，隐藏的那份就重新渲染，紧接着完成重新定位并写库。因此 ⌘S 之后不切回 View 直接关窗，标注也不会丢。
- **标注层等重新定位完成才启用。** store 记着「这批标注是按哪个内容哈希量的」，它和当前文档的哈希不一致时标注层保持关闭，否则会把旧偏移画到新正文上。

## 离开编辑器之前先问

下面每一种操作，有未保存改动时都先弹系统对话框 Save / Don't Save / Cancel：

1. 点 View；
2. 关窗口（红色按钮、⌘W）；
3. ⌘Q；
4. 在本窗口打开任何东西：⌘O 面板、拖文件进窗口、首页 Recent、刷新按钮、在 Finder 里再次打开同一篇（它会被送回这个窗口重新读取，磁盘上的文本会盖掉编辑中的文本）。

Save 成功后继续原操作，保存失败或拒绝覆盖则留在编辑器；Don't Save 丢弃改动继续；Cancel 什么也不做。没有改动时直接放行，不弹窗。设置、导出、首页只是盖在阅读器上，编辑器原样留在下面，不算离开。

对话框用系统原生的：它们会在关窗、退出时弹出，那正是用户期待看到 Mac 标准 sheet 的时刻；页面自绘的对话框还得考虑盖在哪个视图之上。

窗口的关闭请求只在编辑时才由前端接管：被接管的关闭要等页面放行，只读的窗口没理由让它等。

### ⌘Q 与它管不到的退出

系统自带的 Quit 发的是 `terminate:`，而 tao 没有实现 `applicationShouldTerminate:`，app 当场退出，没有窗口能插话。所以 App 菜单里的 Quit 换成了自己的菜单项（仍是 ⌘Q）：从最前面的窗口开始逐个关闭，前一个真正关掉了才关下一个，每个窗口各自走关窗确认，最后一个关掉后 app 退出。

必须一个一个来：一次全关，所有窗口的确认会同时弹出，在一个窗口里选 Cancel 也收不回另一个窗口里已经选了的 Don't Save。中途有窗口选了 Cancel，退出就停在那里（该窗口告诉 Rust 停止）；之前已经关掉的窗口不会恢复。

Dock 菜单的「退出」、注销和关机走的仍是 `terminate:`，没有菜单项可换，这几条路径上未保存的改动会丢。
