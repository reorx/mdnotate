# 阅读器界面：布局、搜索与快捷键

写给要改阅读页面本身的人：视图怎么切换、三栏怎么排、⌘F / ⌘A / 输入法为什么不能用最直接的写法。标注相关的界面见 `annotations-and-export.md`，颜色与排版见 `theme-and-typography.md`。

## 视图切换是覆盖，不是替换

导出、设置、首页以不透明层盖在阅读器之上，**阅读器从不卸载**。否则回到文档时滚动位置、标注层实例、渲染好的 Markdown 全部从头再来。

两个配套细节缺一不可：

- 阅读器根节点自建一个层叠上下文（`relative z-0`），不然标注弹窗会浮到覆盖层之上。
- 被盖住时挂 `inert`，把整棵子树移出 tab 顺序和读屏。

由此带来一条通用规则：**document 级的快捷键要自己判断阅读器是不是在最上面**（当前视图是阅读器，且 ⌘O 面板没开）。覆盖层盖着时按 ⌘F 不该滚动背后的页面。

## 三栏布局

左目录、中正文、右标注。整个窗口不许横向滚动。

- 阅读器根节点必须带 `min-w-0`。它是外层 flex 的子项，默认的 `min-width: auto` 会让整行按「两侧栏 + 正文里最长的不可断行内容」撑开，整个窗口跟着横向溢出。
- 正文滚动容器不横向滚动，超宽内容一律自己内部滚动：代码块本来就是，表格外面包了一层可横向滚动的容器。只包容器不动文本节点，标注偏移不受影响。
- 侧栏宽度存在设置里，范围 160–480px，另有不超过窗口 40% 的上限 —— 窗口再窄正文也至少留 20%。分隔线就是拖拽手柄：拖动时写 store、松手才落盘，双击重置默认。

正文滚动容器可以获得焦点（`tabIndex={-1}`）。标注库本来会给标注容器加同样的属性，但源码视图下标注层是销毁的，所以这一份必须是自己的。有了它，空格 / PageDown / 方向键才滚得动正文。

## 状态栏

在正文列底部、滚动容器外面。字数与体积和标题栏信息浮层是同一个口径、同一处定义，按内容缓存 —— 八兆的文档不该每次渲染都数两遍。复制按钮复制的是文档原文。

## 源码视图

状态栏最右的眼睛按钮，在渲染视图和 Markdown 原文之间切换。

- 它是阅读器的局部状态，换文档重置回渲染视图，不进设置。看一眼源码不该变成下一篇文档的默认阅读方式。
- 纯文本文档不显示这个按钮，渲染视图本来就是原文。
- 切过去时标注层整个销毁：划词不再建 draft，高亮和评论图标一起消失。切回来从 store 重建。
- 两个侧栏在源码视图下变淡并挂 `inert`：点击天然无效，但侧栏自己还能滚。

**三样东西必须跟着视图模式走，漏一个就是静默 bug：**

1. **搜索索引**。它缓存的是真实的 DOM 文本节点，切视图时内容没变但节点全换了。只按内容重置，搜索会指向已经不在文档里的节点。所以索引的版本号由三样拼成：文档 id、内容哈希、是否源码视图。
2. **目录的构建**。标题的 id 是扫渲染后的 DOM 打上去的，切回来标题是全新元素、没有 id，不重跑就再也跳不动。
3. **滚动高亮当前章节**。源码视图下每次标题查找都落空，会把目录第一条一直点亮。

## ⌘F 搜索

### 一个 DOM 节点都不改

命中不是插 `<mark>`，也不是自绘矩形层，而是把 `Range` 交给 **CSS Custom Highlight API**。插元素会动到标注赖以定位的渲染文本；自绘矩形要在每个滚动帧重算。这条路两样都不用，滚动、resize、改字号全部白捡。

代价是需要 Safari 17.2+（macOS 14.2+）。检测不到这个 API 时保留计数与跳转，只是不涂色，搜索栏会亮一个警告图标。

当前命中是从「全部命中」里剔掉、单独放进第二个高亮对象，不靠优先级分层 —— 少赌一条浏览器实现细节，也不会出现半透明蓝叠实心蓝的脏色。

### 两条和直觉相反的实现规则

**高亮对象只注册一次，之后只改它的内容。** 两个高亮对象各 `set()` 一次，之后每次涂色 / 清除都是对象自己的 `clear()` / `add()`；绝不 `delete()`，也绝不用已有的名字再 `set()` 一个新对象。macOS 自带的 WebKit 上这两个操作不重绘，刚失去高亮的字会一直蓝着，直到别的什么把那块重画。测试用假注册表锁住了「只 set 两次、零 delete」，但测不出重绘本身 —— 改这块要去 Safari 里看。背景见 `kb/notes/2026-09-17-css-highlight-repaint.md`。

**高亮的样式规则单独放在 `find-highlight.css`，不放主样式表。** Tailwind 对自己的产物跑的那趟 CSS 处理不认识 `::highlight()` 伪元素，每次构建会刷警告。同理不给它用自定义属性：高亮伪元素是否继承自定义属性，是这个 API 各家唯一没谈拢的地方，所以深浅两套直接写字面值。

### 匹配跑在「规范化文本」上

搜索不是对 DOM 原文做的。文本节点先被折成一条规范化文本，每个字符记着它对应的原始位置：

- **连续空白折成一个空格。** Markdown 段内的软换行在 DOM 里是真实的换行符，不折叠就搜不到跨行的 `quick brown`。
- **块与块之间插一个换行符。** 相邻两个块之间在 DOM 里一个分隔字符都没有，不插就会把上一段结尾的 `fox` 和下一段开头的 `bar` 连起来，误命中 `foxbar`。

搜索词同样只折叠不 trim —— 前导空格是用户要找的东西的一部分。折叠后的搜索词不含换行，所以天然跨不过块边界。

大小写折叠**逐字符做，并校验长度不变**。`'İ'` 转小写后是两个 code unit，整串转小写会让它之后的偏移集体错位，高亮到别的句子。

### 性能上的几个选择

- 索引在第一次搜索时才建，换文档置空。八兆的日志不该让一个从不搜索的读者付这笔钱。
- 命中位置靠二分查找转成 `Range`。不用标注库自带的恢复函数：它每次都从头重走一遍树，几百个命中就是平方级。
- 「从当前视口往下的第一个命中」也是二分：文档流里纵坐标单调不减。
- 命中数封顶 5000，计数显示 `5000+`。
- 收集文本时跳过 `not-annotatable` 的子树，和标注库是同一条规则 —— 评论图标层和弹窗就在同一个容器里。

### 搜索栏的行为

- 搜索栏在滚动容器**外面**，否则会跟着正文滚走。
- 焦点在评论输入框里时，⌘F 与 Esc 一律让路。那里的半截评论不是搜索该丢的。
- **只有真的取走了正文选区，才关掉标注弹窗。** 划词会立刻建一个标注 draft，⌘F 把选区拿去当搜索词就等于放弃那个 draft；但没选区的 ⌘F 不该顺手清掉正在写的评论。

## ⌘A 全选

⌘A 是自己实现的，而且必须在事件的 capture 阶段拦。要同时解决两件事：

- 浏览器原生的全选会连目录、标注列表、工具栏一起选走，复制下来全是垃圾。
- **标注库自己也绑了 ⌘A**：它会把整篇选区建成一条标注，弹出「要不要把整篇文档高亮」的弹窗。库注册在 document 的冒泡阶段，所以要在 capture 阶段把这个键整个拿走。

「拿走这个键」和「阻止默认行为」是两个决定：

- 阅读器在最上面时，两者都做，选区设为正文本身（不含评论图标层和弹窗）。
- 覆盖层盖着时，只掐库、不拦默认。原生全选照常在覆盖层里工作，背后的阅读器是 `inert`，本来就不可被选中。
- 焦点在输入框里时完全放行。

已知残留：⌘A 之后库内部仍留着一个待提交的选区，此时右键会把它提交成整篇高亮。这与「鼠标划一段再右键」是同一条既有路径，明确接受。

## 键盘与输入法

**规则：keydown 里不直接判 `e.key`，一律走 `keys` 模块的谓词。**

原因是浏览器在输入法组字期间照常派发 keydown：Enter 是「把候选词上屏」，Escape 是「丢弃候选词」，方向键是「走候选列表」，它们和普通按键长得一模一样。只判按键的评论框会在用户打中文打到一半时把半句话存下来，或者把整条评论丢掉。

三个必须知道的事实：

1. **React 合成事件上没有 `isComposing`。** 属性和类型都不存在，所以 `!e.isComposing` 恒为真，写了等于没写，且编译期不报错。要读原生事件上的那个。
2. **绑在 document 上的监听拿到的是原生事件**，标志就在事件自己身上。谓词两种形状通吃，并兜底历史约定 `keyCode === 229`。
3. **在 macOS 的 WebKit 上，光看事件不够。** 它把 `compositionend` 派发在导致它的那个 keydown **之前**，所以确认候选词的 Enter 到达时，事件上没有任何东西能把它和用户真心要提交的 Enter 分开。所以启动时要注册一次全局的组字监听：组字结束后延迟 50ms 才清标志，那一窗口内的按键仍算输入法的。

**删掉启动时那一行注册，评论框在真机上就退回原来的 bug，而所有只看事件的测试依然全绿。**

适用范围：

- document 级的**单键**快捷键同样要判。焦点在输入框里组字时，它们照样会收到事件（Esc 关面板、Esc 关搜索栏都踩过）。
- 带修饰键的组合（⌘A / ⌘F / ⌘G）不用判，输入法不消费它们。
- handler 顶部判过一次组字并 return 之后，同一个 handler 里再比较按键是可以的。

背景与实测数据见 `kb/notes/2026-08-16-ime-enter-escape.md`。
