# 为当前文档导入默认格式的 Markdown 标注

## PRD

### 背景与目标

用户已有从 mdnotate 导出的 Markdown 标注，希望将它们恢复到当前打开的文档，重新显示高亮和评论，继续修改并保存。用户已确认首版无需支持自定义导出模板。

### 导入交互

- 当前文档提供 Import 入口，粘贴默认格式的导出文本，先预览识别结果，再提交导入；取消不改变已有标注。
- 预览列出引用、评论和处理结果，区分可导入、重复、找不到原文、位置有歧义及格式问题。
- 导入成功后立即显示正文高亮、评论图标与标注侧栏，支持现有的编辑评论、删除、跳转和重新导出操作，重开文档仍然保留。
- 导入只追加；保留已有标注，完全相同的条目跳过。相同引用但不同评论不静默覆盖已有评论。
- 部分条目无法定位时明确列出原因，只导入预览中有效的条目；没有有效条目时不能提交。

### 格式与异常处理

- 支持现有默认导出：文档路径标题、引用块原文、可选评论、条目间空行。支持纯高亮、多行引用、多行评论。
- 引用必须在当前正文唯一匹配；找不到或多处出现时不猜测位置。不依赖导出的路径自动打开或修改另一篇文档。
- 默认导出没有保存标注位置、ID 和创建时间，恢复后按新标注处理。
- 对无法可靠区分引用与评论的输入明确报告格式问题；不能宣称任意 Markdown 都能无损还原。
- 导入期间文档发生切换或内容改变时，使旧预览失效，避免导入到错误文档。存储失败必须提示，不能声称已经持久保存。

### 不做的事

不支持自定义模板、批量跨文档导入、模糊匹配或自动选择重复引用的位置；不改变现有导出格式，不新增备份格式或云同步。

### 验收标准

1. 从默认导出复制纯高亮及带评论的条目，可在同一正文恢复对应位置。
2. 多行引用与评论正常恢复，引用正文的空格、标点和 Markdown 字面字符不被随意改写。
3. 不刷新、不重开文档即显示导入结果，能立即编辑、删除、跳转与再次导出。
4. 重复导入不会产生完全相同的新条目，也不会覆盖现有不同评论。
5. 未匹配、歧义、格式错误有清晰预览；取消不写入，部分有效输入可仅导入有效项。
6. 重开文档保留导入标注及后续修改；切换文档、编辑状态及存储错误不会产生错误的成功反馈或跨文档写入。

## Tech Design

### 现状

- `src/lib/template.ts` 的默认外层为 `# {{filePath}}\n\n{{annotations}}`，内层为 `> {{highlight}}\n{{comment}}`；多行引用每行补 `> `，空评论整行省略。
- `annotationsToMarkdown`（`src/lib/annotations.ts`）按位置排序后用两个换行连接条目。`ExportView.tsx` 负责复制完整输出。输出不包含 ID、偏移或原始时间。
- `Annotation` 包含 quote、start/end、comment、ID 和时间。写入必须经过 `src/lib/annotate.ts`；现有流程先更新 store，再用 `recordAnnotation` 写库，失败显示错误。
- `use-text-annotator.ts` 初始化时 `setAnnotations`，后续 annotations 的 effect 只更新评论图标。因此只增加 store 条目不足以显示导入高亮。
- `collectAnnotatableText`（`reanchor.ts`）遍历正文文本节点并排除 `not-annotatable`，可复用取准确偏移；`reanchorAnnotations` 按旧位置找最近匹配，不适用于没有旧位置的导入。
- `Reader.tsx` 持有 annotator.containerRef；`App.tsx` 的顶栏和 overlay 承载 Export。Reader 在 overlay 下保持挂载。源码视图、编辑模式和 hash 迁移期间不可据源码计算标注位置。

### 方案与数据变动

解析、定位、去重采用独立纯函数，UI 只收集输入、展示预览和触发提交。保留现有导出与数据库 schema，不改 migration。默认模板常量定义兼容格式，不从当前自定义设置推断格式。

新增候选与预览类型，携带原始条目序号、quote/comment、匹配状态及可导入偏移。预览绑定当前 docId/contentHash 和输入版本；提交前重新验证当前文档、可标注状态、正文与已有条目，不能使用过期预览。

### 逻辑变动

1. 新增 `src/lib/import-annotations.ts`（建议名称）：解析默认导出，定位和去重。只把 CRLF/CR 统一为 LF；引用行仅剥离导出加上的一层 `> `，保留原文空白与嵌套 `>`。可选识别开头路径标题；不使用它路由文档。不要用 Markdown 渲染器解释引用内部的强调等语法，因为这里是渲染后的字面文字。多行评论保留段落空行，条目边界按默认导出语法识别并在预览显示。
2. 对每条非空 quote 在准确渲染文本中查所有匹配：唯一匹配才可导入，零次为 missing，两次以上为 ambiguous，包含重叠出现。不能 trim 或压缩正文空白后直接套偏移。以 start/end/quote/comment 的完整一致性判断已有条目和本批次重复；不同评论保留为独立标注。
3. 扩展 `annotate.ts` 提供导入入口，分配新 UUID 与时间，通过现有 store 和存储漏斗追加。提交绑定明确 docId/hash，异步写入不能在 await 后重新读取另一个文档作为目标。返回可供 UI 区分内存导入与持久化失败的结果；避免吞掉写入失败后仍显示持久化成功。先沿用现有存储能力，若引入批量操作应保持浏览器 fallback 对等且验证失败语义。
4. 扩展 `use-text-annotator.ts` 的程序化追加接口，将新增条目通过库 API 同步到活着的实例，并刷新 markers；库方法先查本地类型/API，需要时用 context7。避免每次 store 更新全量 setAnnotations 或重建实例，从而破坏选区、草稿及滚动位置。不能重复触发 onCreate 导致双写。若选择 store 差异同步方案，必须覆盖同样的生命周期要求。
5. 新增导入 UI，优先在 Reader 内管理局部面板以直接取得正文容器，入口放在现有标注操作附近；组件命名与具体布局可依现有 UI 确定。面板在正文可标注子树外，或挂 `not-annotatable`。编辑/源码视图和迁移期间不可导入，提供可理解的禁用原因。无标注时仍可进入。关闭或成功提交后回到阅读，展示实际结果并打开侧栏。
6. 面板存在时暂停 Reader 的正文快捷键，中文 Enter/Esc 用 `keys.ts`；沿用 neutral/bg-page/bg-raised 与 IconButton。文档切换即清除面板预览。对已有侧栏评论草稿保持现有行为，不让导入默默丢草稿。
7. 更新 `kb/docs/annotations-and-export.md` 的导入协议、限制和运行时同步规则；必要时更新 AGENTS.md 对应不变量，不能保留“所有标注仅初始化读取”而不解释显式导入例外。

### 测试与验证

- 纯逻辑 BDD：使用真实 `annotationsToMarkdown` + 默认内外模板产生 fixture，再解析、定位；覆盖纯高亮、带评论、多段评论、多行引用/空引用行、CRLF、中文/emoji、美元符、字面 Markdown、首尾空格、嵌套引用字面内容。
- 边界：无输入、只有标题、无引用、无匹配、重复位置（含重叠）、完全重复条目、同位置不同评论、混合有效无效；正文有列表编号、Front Matter、图片状态时用现有文本收集规则验证偏移。不要修改正文文本节点或渲染 hash 来解决导入。
- 默认格式天然没有转义条目分隔符：评论自己含引用块时可能与下一个标注无法区分。为可识别歧义提供明确格式错误，预览让用户核对；不承诺可以恢复所有历史评论的原始边界，且不私自改变导出协议。
- 服务行为测试：取消/无有效项不写入，提交复检发现文档变化拒绝，重复点击不双写，导入后评论更新/删除可持久化，模拟写库失败显示真实结果。组件不加单测；库同步用浏览器真实交互验。
- 浏览器验收：默认导出 → 删除原条目 → Import 粘贴 → 预览 → 导入 → 立即检查正文高亮/图标/侧栏 → 点击编辑 → 保存 → 再导出 → 重开确认；另验重复导入、部分失配、取消、文档切换、空标注入口、明暗主题、窄窗口以及中文输入法按键路径。不要把 localStorage 验收声称为 SQLite 验收；Tauri 存储复用现有路径，若改数据库写法须按 verification 文档做 dev SQLite 验证。
